How desks get data for reports

Each ticker desk writes research for Latent. The numbers in those reports come from a shared filing cabinet and a shared set of tools — not from one-off spreadsheets. This page explains who pulls, who cleans, who analyzes, who fixes the tools, and who publishes the live URL you read.

Who does what

Think of it as a small newsroom with a shared library. Desks own the story. Shared tools own the facts. Product and Cursor keep the library working. Tylor (Chief of Staff) ships the finished page to you.

Desk bot (Zillow, Spotify, Alphabet, IBKR…)

Owns one ticker. Runs the shared tools to pull filings and refresh numbers. Reads the clean series. Does the investment analysis, writes the letter, and decides which charts matter.

Does not edit the shared filing tools.

Shared filing tools (Tylor)

The library everyone runs. Pulls SEC filings and curated investor-relations PDFs into a shared cabinet. Extracts printed numbers into standardized tables. Pulls market prices and consensus EPS where configured. Cleans and standardizes so desks never invent their own parsers.

Shared cabinet (tylor-data)

One filing cabinet on the shared computer. Raw documents go in; clean period-by-period series come out. Every desk charts from the same place.

Product

When a number is printed in a filing but missing or wrong in the clean tables, Product writes the fix specification. Desks surface the gap; they do not patch the tools themselves.

Does not write pack prose.

Cursor cloud agents

Implement Product’s approved tool and pack-template changes in the repos. Merge when green. Desks then pull the updated tools and re-run.

Tylor (Chief of Staff)

Coordinates desks, quality-reviews the pack (especially writing voice), publishes the live research-site page, and sends Latent only the URL.

Designer

Owns brand look — tokens, lockups, hub chrome. Not numbers or thesis.

Latent

Reads the published report URL. Escalates product priorities when something systematically needs fixing.

Role map — who runs tools, who fixes them, who publishes

Principles

Short rules the desks live by. Each one has a concrete habit behind it.

  • Prefer what the company printed Printed facts from filings beat estimates or reconstructed guesses every time.
  • Blank beats wrong Never invent a number to fill a chart. An empty cell is honest; a made-up one is not.
  • One shared source of truth Clean series live in the shared cabinet. Desks bind charts to that series — they do not keep private number books.
  • Labeled derivation only when print is absent If a ratio can be built from printed parts and the company never printed the ratio itself, derive it and say so. Otherwise leave it blank.
  • Tool bugs go up the chain Desk → Tylor CoS → Product → Cursor. Never a local hack on shared scripts.
  • Data lock first, then writing, then publish Numbers settle before prose. Prose settles before the live URL goes to Latent.

The pipeline

From claiming a ticker to the URL in Latent’s inbox, the path is the same every time. Concurrent SEC fetches stay under a shared lock so desks do not step on each other at EDGAR.

1

Claim ticker

A desk is assigned (or claims) one company. From then on, that desk owns the analysis and the letter.

2

Pull filings + optional IR extras

Shared tools fetch SEC filings into the cabinet. Curated investor-relations PDFs can come along when they add printed detail the filings lack.

3

Extract clean metrics

Printed numbers land in standardized analytics tables — period by period, field by field. Desks read these tables; they do not re-parse filings by hand.

4

Market / PE feeds

Where configured, market prices and consensus EPS join the same clean layer so valuation charts share one backbone with the fundamentals.

5

Desk analysis & brief

The desk reads the series, forms a view, picks charts, and writes the research letter. Narrative belongs to the desk.

6

Research-pack webpage

The pack generator turns desk series + narrative into the HTML page Latent will eventually read.

7

CoS review

Tylor quality-reviews — voice, clarity, and that the pack matches the data lock. Fixes go back to the desk, not into the tools.

8

Live research-site URL → Latent

CoS publishes to the research hub and sends Latent the URL only. No PDF or HTML attachment in chat.

End-to-end data pipeline — claim through publish

Key components

Plain names for the pieces you will hear desks and Tylor talk about.

Filing cabinet layers

Raw filings are the documents as pulled from SEC (and optional IR PDFs). Clean analytics tables are the warehouse desks chart from — standardized, period-by-period series. An older middle layer of “processed summaries” exists historically; desks do not use it for charts or numbers in the pack.

Metric dictionary / contracts

A shared list of which fields must bind when the filing prints them. If a contracted field is missing after extraction, the run fails loudly. That way holes do not silently return as blank charts later.

Research packs

The HTML report generator. It turns the desk’s clean series plus narrative into the page Latent reads. Desks own the words and chart choices; the template owns the layout.

Research site hub

Where published digs live. After CoS review, the pack is published here and Latent gets the URL — nothing else.

Printed facts are preferred. A derived figure is allowed only when labeled and the print is truly absent — for example a margin computed from printed revenue and printed profit. Desks never silently invent.

What Cloud agents do vs what desk bots do

Different jobs. Mixing them is how tools get forked and numbers drift.

Desk bots

  • Run the shared filing tools as-is
  • Read clean series from the cabinet
  • Analyze, write the letter, choose charts
  • Surface gaps to Tylor / Product
  • Rebuild the pack after tools are fixed

Cursor cloud agents

  • Implement Product’s approved fix specs
  • Change shared tools and pack templates in repos
  • Merge when checks are green
  • Do not own ticker thesis or pack prose
  • Do not publish to Latent

Desks never edit Tylor scripts or config on the shared computer. When a tool needs changing, the path is Product → Cursor → desks pull and re-run.

When something is missing

A blank chart is not always a bug. First ask: did the company print the number? Then follow the right branch.

Gap escalation — printed-but-missing vs never-printed

Printed but missing or wrong

Desk tickets Product through Tylor. Product writes the fix spec. Cursor ships it. Desks pull the updated tools, re-extract, and rebuild the pack. No local patches on shared scripts.

Company never printed it

That is an honest gap. Leave it blank, or — only if the parts were printed — show a labeled derivation. This is not a tool bug and should not become a Product ticket pretending it is.
